1 · Critique

  1. The calendar leads. Header, week strip and legend take the first ~300px. Today’s action starts below the middle of the screen.
  2. Status needs a legend. Five icon shapes in four colors have to be decoded before the strip makes sense.
  3. Progress is a loose sentence. “1 of 4 workouts completed” floats between strip and card, tied to neither.
  4. Tuesday appears three times: in the strip, the Today card and the Workouts list. The list also repeats past days.
  5. Every attribute is a pill. Status, intensity, exercise count and time share one badge style, so nothing ranks above anything else.
  6. Attention items stack as notices (unfinished session, long break) above the Today card and compete with it.
  7. Rest day reads as empty: a sentence and an outline button, with no mention of the next workout.
  8. “Calendar” as the first tab describes a tool, while the screen is the user’s daily home.

2 · Information architecture

  1. 1Header — date, greeting, one line of context derived from state. Absorbs the long-break notice.
  2. 2Today card — one state, one primary action. Attention items (unfinished session, missed workout) become the card’s state instead of separate notices.
  3. 3This week — count, segmented bar, compact strip, one insight. Week navigation sits quietly in its header.
  4. 4Up next — up to three future workouts, grouped in one card, with a link to the full schedule.
Navigation: Today · Programs · Progress · Profile. The first tab becomes Today (/today, sr: “Danas”). The existing /calendar and /calendar/[date] routes stay as the full schedule, reached from “Full schedule”, day taps and week navigation. No new destinations.

Redesign · interactive — tap Start, Continue, week arrows, days, rows

3 · Today-first home

The eye goes greeting → deep-teal Today card → coral button. It is the only coral surface on the screen, so there is one obvious thing to do. Everything below supports it.

  1. AContext line answers “what should I do today?” in words before the card does it visually.
  2. BToday card uses the existing --color-hero surface from the welcome screen. Time and intensity sit on the eyebrow line; the title is the largest text on the page; only one fact (exercise count) sits under it.
  3. CWeek card merges the strip, the count and the insight. Segments show planned workouts only, so “1 of 4” and the bar always agree. No legend: each status has a distinct shape and the full label is in the accessible name.
  4. DUp next lists future workouts only; today and past days are never repeated.
Recommendation, not in data yet: estimated duration. Toggle “Show duration” in Tweaks to preview it. It would need an estimate from sets × (work + rest_seconds) per program day; until then it stays hidden.

Minimum 12px (day labels, nav). All sizes map to rem so Dynamic Type / browser zoom scales them; no fixed heights on text containers, only min-heights.

Spacing, surfaces, elevation

  • 4-pt grid. Screen gutter 20. Zone gap 22. Inside cards 14–18. Row padding 14/16.
  • Hero radius 28 (--radius-sheet), --shadow-raised. One per screen.
  • Card radius 20 (--radius-card), --shadow-card. No borders on cards.
  • Controls radius 14 (--radius-control). Primary 56 tall, secondary text buttons ≥44.
  • Grouping: rows share one card and divide with a 1px surface-muted line instead of each being a card.
  • Pills limited to two uses: intensity on the hero and the “Not logged” flag.

Status rules

Shape carries meaning, color reinforces it, the accessible name spells it out (“Tuesday 29 September: Full body — Strong, Planned (today)”).

Components

  • HomeHeader — date, greeting, context.
  • TodayCard — variants: planned, in_progress, completed, rest, missed, unplanned, no_program. Reuses WorkoutCta logic.
  • WeekSummary — header + nav, count, WeekSegments, compact WeekStrip, optional Insight.
  • UpcomingList + UpcomingRow.
  • Existing: Button, Card, StatusIcon, LiveDot, Skeleton, OfflineBanner, BottomNav.

Icons & motion

  • lucide, 2px stroke (2.4 when active or on small marks), 16/18/20/24 sizes. Always paired with text or an aria-label.
  • Card entry: existing enter stagger (40ms). State change: hero cross-fades 240ms ease-standard.
  • Progress segment fills with animate-draw when a workout completes; live dot uses animate-live.
  • All motion respects the existing prefers-reduced-motion reset; nothing depends on animation to be understood.

8 · Why this is more useful

  • The day’s answer and action sit in the first 450px, above the week, instead of below a legend.
  • One coral button per screen. The action changes with state (Start → Continue → View summary) while its position stays fixed.
  • Rest days show the next workout and treat recovery as part of the plan.
  • Missed workouts become a decision (move or skip) instead of a silent grey dot, which keeps the weekly count honest.
  • Week progress uses one number and one bar that always match; no legend to learn.
  • Nothing is invented: every value comes from the current tables, and the one recommended addition (duration) is marked as such.
